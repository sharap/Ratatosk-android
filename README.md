# Ratatosk для Android

Клиент мессенджера Ratatosk: Kotlin и Jetpack Compose поверх ядра
[`ratatosk-core`](https://github.com/sharap/ratatosk-core), написанного
на Rust.

Переписка шифруется, адресов на сервере нет, и сообщение идёт тем путём,
какой доступен прямо сейчас: по локальной сети, по Bluetooth, через Tor,
через почту или через меш Yggdrasil. Ядро выбирает ступень само и честно
говорит клиенту, куда уйдёт следующее сообщение.

## Что умеет

* личные чаты и группы, вложения с превью, реакции, ответы и правки;
* присутствие «рядом» — контакт слышен в локальной сети или в эфире Bluetooth;
* приглашение по ссылке `ratatosk:v0:…` и по QR; отпечаток сверяется голосом,
  и до сверки контакт показывается непроверенным;
* режим терминала: телефон остаётся хранителем ключей, а десктоп работает
  как сопряжённое устройство (ссылка `ratatosk:v0:pair:…`);
* приём «Поделиться» из других приложений и открытие ссылок `ratatosk:`.

## Состояние

Ранняя версия, 0.1.0. Готовые сборки — на [странице
релизов](https://github.com/sharap/Ratatosk-android/releases); они помечены
предварительными, и это не формальность: снаружи приложение пока никто не
проверял.

**Сборка, собранная без своего ключа, раздаче не подлежит** — см.
[«Подпись»](#подпись).

## Сборка

Нужны:

* JDK 11 или новее (Gradle подтягивается обёрткой, версия 9.5);
* Android SDK, `compileSdk 37`, минимальная поддерживаемая версия — Android 9 (API 28);
* Rust с `cargo` и [`cargo-ndk`](https://github.com/bbqsrc/cargo-ndk), Android NDK;
* исходники [ядра](https://github.com/sharap/ratatosk-core) рядом с этим
  репозиторием — путь зашит в `app/build.gradle.kts`:

```sh
git clone https://github.com/sharap/ratatosk-core
git clone https://github.com/sharap/Ratatosk-android
```

```
.
├── Ratatosk-android/   <- этот репозиторий
└── ratatosk-core/      <- ядро
```

Дальше обычное:

```sh
./gradlew assembleRelease
```

Сборка сама соберёт ядро под `x86_64` и `arm64-v8a` (`cargo ndk`, профиль
`release-android`, возможности `tor mail ygg-node nostr`) и сгенерирует
Kotlin-привязки через UniFFI. Собранные `.so` кладутся в
`app/src/main/jniLibs/` и в репозиторий не попадают: это артефакт ядра,
а не исходный код этого проекта.

Если ядро обновилось, привязки стоит пересобрать начисто — Gradle охотно
берёт их из кэша:

```sh
./gradlew :app:assembleRelease --rerun-tasks
```

## Подпись

Ключ описывается в `keystore.properties` в корне проекта. Файла в
репозитории нет и быть не должно — в нём пароли; рядом лежит образец:

```sh
cp keystore.properties.example keystore.properties
```

```properties
storeFile=app/keystore/release.jks   # относительный путь — от корня проекта
storePassword=…
keyAlias=release
keyPassword=…
```

Неполный или неверный файл останавливает сборку с указанием, чего не
хватает: подписать «чем получится» хуже, чем не собрать.

**Пока `keystore.properties` нет**, `release` подписывается отладочным
ключом, и сборка об этом предупреждает. Раздавать её нельзя, и причина не
в формальности:

* отладочный ключ общий для всех — его пароль (`android`) и псевдоним
  (`androiddebugkey`) записаны в документации Android, так что подделать
  такую подпись может кто угодно. Для мессенджера, где подпись —
  единственное, чем система отличает обновление от подмены, этого хватает,
  чтобы не раздавать;
* в Google Play такую сборку не примут;
* лежит он у каждого свой (`~/.android/debug.keystore`), поэтому собранное
  на одной машине не обновится поверх собранного на другой.

## Устройство

```
app/src/main/java/chat/ratatosk/android/
├── MainActivity.kt      точка входа, приём внешних интентов и ссылок
├── core/                мост к ядру: запуск, журнал, радио Bluetooth
├── ui/                  экраны на Compose
├── service/             работа в фоне, уведомления, переживание перезапуска
├── data/                секреты устройства, настройки
└── util/                вспомогательное
app/src/main/java/org/ratatosk/core/   привязки, порождённые UniFFI
```

Привязки `org/ratatosk/core/ratatosk_ffi.kt` генерируются из ядра и лежат
в репозитории только ради чтения кода и подсказок среды разработки; править
их руками бесполезно — следующая сборка перезапишет.
